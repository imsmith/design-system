# Design System

A normative reference for visual identity and user experience — the child of a
**graphic standards manual** (color, type, grid, marks, material) and a **UX
manual** (components, patterns, motion, voice). It documents shared, named design
decisions and the rules for using them, so that everything built from it agrees.

It is not a component library, a CSS framework, or a drawing tool. It is the set
of decisions those things are obligated to honor.

## How this is organized

- `manual/` — the chapters. Human-readable, normative, illustrated with usage rules.
- `tokens/` — the machine-readable backbone: the canonical decisions as `edn`
  data, plus their **generated serializations**: `colors.css`, `typography.css`,
  `spacing.css`, `effects.css` (custom properties) and `design_system_tokens.ex`
  (the same data for the BEAM). `fonts.css`, `base.css`, and `components.css`
  (the component styles every consumer shares) are hand-authored. `styles.css`
  at the root is the one file a web consumer links.
- `assets/` — canonical visual assets: `assets/marks/sprite.svg`, the mark/icon
  library as an SVG symbol sheet (`currentColor`). `fonts/` holds the
  self-hosted Martian families.
- `gallery.html` — every component on one page, one card each, on the real
  classes, with theme and mode switch. Generated by `tools/gallery.tcl`.
- `specimen.html` — the rendered proof: every token on one page with a theme
  and mode switch. Generated by `tools/specimen.tcl`; never edited by hand.
- `tools/` — the checks and the generators. The Tcl ones run on the host; the
  APCA verifier and markdownlint run inside a distrobox, never the host.
- `design.md` — the agent-facing contract: the manual condensed for anything
  that emits color, type, spacing, marks, motion, or copy from this system.

## Consumers

Nothing here is a component library. The consumers live in their own repos
and vendor the generated files from a pinned commit of this one:

- [gos-js](https://github.com/imsmith/gos-js) — React reference components,
  the Operations Console UI kit, and the Claude design skill bundle.
- [gos-ui](https://github.com/imsmith/gos-ui) — Phoenix LiveView components
  and Livebook helpers.

## Verify

```bash
make gen        # regenerate every serialization from the edn
make specimen   # regenerate specimen.html
make gallery    # regenerate gallery.html
make check      # edn parse + hex drift + links + generated freshness (host), APCA + markdownlint (distrobox)
```

`check` exits non-zero on any failure. Edit the `edn`, run `make gen`, commit
both. The distrobox is `design-system`, from `docker.io/library/node:22`; the
Makefile header shows how to create it.

## Backbone

The canonical decisions are authored as `edn` under `tokens/`:

- `color/spectrum.edn` — the diverging temperature spectrum (the data color scale).
- `color/status.edn` — the vivid alert ramp and its OASIS CAP mappings.
- `color/opinion.edn` — the STIX `opinion` diverging mapping.
- `color/markings.edn` — the STIX TLP fixed marking palette.
- `color/themes.edn` — the three anchor themes (chrome roles, light and dark; APCA-verified).
- `typography.edn` — the duo, scale, weights, terminal degradation.
- `space.edn` — base unit, scale, density modes, grid, terminal cells.
- `marks.edn` — the mark registry (SVG ids, Nerd Font / Unicode / ASCII fallbacks).
- `material.edn` — glow levels.
- `components.edn` — the state matrix.
- `motion.edn` — durations, easing, the critical pulse.
- `voice.edn` — register and the status lexicon.

Geometry for marks lives in `assets/marks/sprite.svg`.
